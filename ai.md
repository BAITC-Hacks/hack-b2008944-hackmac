# EKT — ИИ-консультант по электротехнике

React + FastAPI + OpenAI Responses API. Ассистент уточняет задачу, ищет товары
через существующий EKT API, читает характеристики и предлагает возможные аналоги.
Фронтенд восстановлен из `origin/feature/frontend`; демонстрационные ответы удалены.

## Запуск на macOS в VS Code

Откройте **всю папку проекта**, содержащую `backend` и `ekt-ai-frontend`.
Нужны Python 3.11+ и Node.js 22.12+.

Первый терминал, из корня проекта:

```sh
python3 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
cp -n backend/.env.example backend/.env
```

Заполните `backend/.env`:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI
OPENAI_MODEL=gpt-4.1-mini
EKT_API_URL=https://ekt.kz/api
EKT_API_USERNAME=ваш_логин_EKT_API
EKT_API_PASSWORD=ваш_пароль_EKT_API
```

Ключ и доступ к каталогу остаются на сервере. `.env` исключён из Git. Не помещайте
секреты в `VITE_*`, в исходники или сообщения чата. Подписка на чат здесь не
используется: запросы выполняются по указанному ключу OpenAI API.
При проверке 23.09.2026 каталог EKT без авторизации вернул HTTP 401 — нужны
действующие учётные данные API. Для смены `.env` перезапустите backend.

Запуск backend:

```sh
cd backend
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

Во втором терминале, из корня проекта:

```sh
cd ekt-ai-frontend
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173>. Документация API: <http://127.0.0.1:8000/docs>.
В разработке Vite проксирует `/api/*` к FastAPI, поэтому фронтенд работает без
дополнительной настройки `.env`. Встроенные задачи VS Code: **Terminal → Run Task →
EKT: Запустить всё**. Для отладки установите рекомендованное расширение Python
Debugger, выберите **EKT: Чат целиком** и нажмите F5. Сначала установите зависимости
и создайте `backend/.env` командами выше.

## Что подключено

- `POST /chat` — ответы модели, инструменты поиска/карточек/аналогов и память диалога.
- Карточки берутся из EKT: модель выбирает только проверенные в текущем запросе ID.
  Если модель возвращает неизвестный ID, ответ отклоняется. Текстовые объяснения
  генерируются моделью; их качество нужно проверять на ваших примерах подбора.
- До 6 вызовов инструментов на сообщение; повтор одинакового вызова использует
  его результат внутри этого запроса. Есть таймауты, ограничение одновременных
  запросов и 20 сообщений в минуту на IP.
- История хранит 8 последних ходов, удаляется после часа неактивности; максимум
  500 диалогов. Одновременные сообщения одного диалога отклоняются с HTTP 409.
- Модель не имеет инструмента изменения корзины. Добавление выполняется отдельным
  запросом после подтверждения, с повторной проверкой цены и остатка на сервере.
- Интерфейс показывает настоящие ошибки подключения, не подменяет их демо-ответами.
- `GET /health` возвращает `assistant_configured`: это наличие ключа в настройках,
  а не проверка его действительности или доступности каталога.

Файлы для настройки: `backend/assistant_prompt.txt` — поведение консультанта;
`backend/assistant_service.py` — модель и инструменты; `backend/ekt_client.py` —
API каталога; `ekt-ai-frontend/src/App.jsx` — интерфейс и подключение HTTP API.

## Контракт чата

```http
POST /chat
Content-Type: application/json

{"session_id":"8c30cc18-e1ca-4391-9fa8-6dd63f888999","message":"Нужен автомат C16"}
```

`session_id` — случайный идентификатор из `crypto.randomUUID()`, общий для чата
и корзины. Поддерживается также старое имя `sessionId`. Если поле пропущено, сервер
создаёт UUID. Клиент должен сохранять его и передавать в следующих запросах.
Нельзя использовать один фиксированный ID для всех посетителей. Историю сообщений
с клиента принимать не нужно — она хранится на backend.

Ответ: `session_id`, `reply` и `products`. В карточках: `id`, `title`, `article`,
`price`, `stock`, `url`, `image`, `requires_technical_review`. Неизвестная цена или
остаток передаются как `null`, а не ноль. Текст нужно выводить как обычный текст,
не как HTML. Ошибки: `422` — неверный запрос, `429` — лимит, `502/503/504` —
недоступность или некорректный ответ внешнего сервиса.

Пример для другого фронтенда:

```js
const response = await fetch('/api/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ session_id: sessionId, message: userText }),
})
const data = await response.json()
if (!response.ok) throw new Error(data.detail)
// data.reply — текст ответа; data.products — подтверждённые карточки каталога.
```

## Проверки

```sh
cd backend
.venv/bin/python -m unittest discover -s tests -v
```

```sh
cd ekt-ai-frontend
npm run build
npm run lint
```

Автотесты подменяют HTTP-ответы OpenAI и данные EKT и не расходуют API-кредиты.
Они проверяют поиск через инструменты, память и изоляцию диалогов, ошибки,
неизвестные ID, таймауты, CORS, лимиты и подтверждение/остатки корзины.
Для проверки живых сервисов после заполнения `.env` отправьте артикул реально
существующего товара, затем «А есть аналог дешевле?» и запрос с отсутствующим
артикулом. Сверьте найденные цены, остатки и характеристики с каталогом.

## Границы текущей интеграции

Существующий API ищет перебором страниц, а не полнотекстовым поиском по всем SKU.
`CHAT_SEARCH_MAX_PAGES=10` ограничивает область поиска. `partial=true` означает,
что каталог просмотрен не целиком: отсутствие результата не доказывает отсутствие
товара. Для полного каталога нужен серверный поисковый endpoint EKT или отдельный
индекс, обновляемый из каталога. Текущий клиент ожидает список в `items` и поля
`id`, `name`, `article`, `price`, `quantity`, `url`, `image`, `properties` в карточке,
как в исходном backend; формат реального API нужно подтвердить с авторизацией.

Память диалогов, лимиты и корзины находятся в RAM одного процесса. Запускайте
один worker; перезапуск очищает данные. Для нескольких workers и постоянных
корзин перенесите состояние в Redis/БД и свяжите с авторизацией сайта.
Корзина здесь — список подбора; checkout и корзина личного кабинета ekt.kz не
интегрированы. Кнопка оформления не имитирует заказ.

На сайте направьте HTTPS `/api/*` на FastAPI со снятием префикса `/api`, либо
задайте публичный `VITE_API_URL` при сборке фронтенда и точный `CORS_ORIGINS`
на backend. Ограничьте частоту запросов также на reverse proxy. При проксировании
доверяйте заголовкам IP только от своего proxy. Эти изменения подготовлены для
локального запуска; публикация на действующий ekt.kz не выполнялась.

Справка реализации: [OpenAI function calling](https://developers.openai.com/api/docs/guides/function-calling)
и [GPT-4.1 mini](https://developers.openai.com/api/docs/models/gpt-4.1-mini).
